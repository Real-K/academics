# 한국 기업 식별자 연결 사다리

식별자: **bn10**(사업자번호 10자리; 사업장 단위일 수 있음) · **bn6**(일부 등록부의 앞 6자리) · **corp_code**(DART) · **ticker**(상장) · **법인등록번호** · 기업명(국문/영문, 법인격 표기 변형).

| 단계 | 방법 | 주의 |
|---|---|---|
| 1 | bn10 정확 일치 | 본사 vs 사업장 번호 불일치("쫑나는 현상") 가능 → 2단계로 |
| 2 | bn6 + 정규화 기업명 | `name_normalize.py`; bn6 는 유일하지 않다 |
| 3 | 기업명 정규화 일치(국문) | 홀딩스/홀딩즈, (주) 위치, 띄어쓰기 |
| 4 | 영문 기업명 → 한글 후보 생성 → 유사 매칭 | PitchBook 등 영문 소스. 후보를 여러 개 두고 근거 남김 |
| 5 | LLM 유사도 판정(근거 필수) | "가장 유사한 기업"을 확신도와 근거 문장으로. 1:1 이 아닐 수 있음 |
| 6 | 외부 조회(nicebizline 대표 사업자번호 등) | 스킬 `nicebizline-*` |
| 7 | **PI 수작업 adjudication 패키지** | `pi_package_template.md` — 남은 것만 |

## 회수 이후 규칙 (P-014 283→379 의 교훈)
- 회수된 처치기업은 **대조 풀에서 제외**한다(제외집합 = 처치 전체). 남으면 오염.
- 정본 표본 파일 하나를 지정하고 sha256_16 을 CLAUDE.md 에 적는다. 코드는 그 파일을 **읽는다** — 소스에서 재구성하지 않는다.
- 회수 뒤 **기각했던 설계를 전부 재점검**한다(표본 확대는 설계 레버).
- 회수 방법별 provenance(어느 단계에서 매칭됐나)를 기업별로 기록. 공개 저장소에는 올리지 않는다.
