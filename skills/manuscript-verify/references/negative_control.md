# 검증기 음성 대조 프로토콜

검증기가 "통과"만 내면 믿을 수 없다. 설치·수정 직후 **결함을 주입해 반드시 실패하는지** 본다.

1. 원고 사본에 폐기값을 되살린다 — 예: `hazard 1.288 [1.054, 1.575]` → `1.2512 [1.031, 1.519]`, 존재하지 않는 수치 `0.7777` 하나 추가.
2. `verify_draft.py <사본>` → 미확인 ≥1 **그리고** 폐기 수치 ≥1, exit 1 이어야 한다.
3. 캡션 사본에 구판 제목·중복 번호·`Table 9` 를 넣고 `VERIFY_CONFIG` 로 그 사본을 가리켜 `check_refs.py` → 캡션 문제 ≥3, exit 1.
4. 원장 사본에 같은 `claim_id` 두 행 → `ledger_lint.py` exit 1.
5. 결과를 기록에 남긴다("음성 대조 4/4 검출"). 검출 못 한 항목이 있으면 검증기를 고치기 전엔 "검증 통과"를 주장하지 않는다.

## 알려진 사각지대(이미 막았지만 새 프로젝트에서 재확인)
- 코드 안에만 있는 캡션 블록 → `caption_source` 설정
- 쉼표 없는 4자리 이상 수(12480) — 정규식이 `\d{1,3}(,\d{3})*` 면 통째로 놓친다
- 표 재번호 → 수치는 불변이므로 `check_refs` 로만 잡힌다
- log point ↔ percent 혼용은 어느 검증기도 못 잡는다 → `academics:narrative-audit` 어휘 규칙
