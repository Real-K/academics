# CLAIMS_LEDGER 스키마

| 열 | 뜻 | 규칙 |
|---|---|---|
| `claim_id` | 청구 식별자 (C12, D04a, E01h…) | **유일**. 새 행을 추가할 때 기존 id 와 충돌하는지 먼저 확인(`ledger_lint.py`). 접미 문자(a,b,c…)는 같은 패널의 부속 통계 |
| `exhibit` | 인용되는 전시물 (T3, F1, OA) | |
| `claim` | 한 줄 서술 | 폐기 시 `[SUPERSEDED -> 대체행 (산출물)]` 접두 |
| `value` | 보고 값 | 산출물의 반올림 그대로 |
| `ci95` | `[lo, hi]` | **추정치의 구간만.** 위약 귀무 범위를 여기 넣지 않는다(P-014 E01 사고: 귀무 CI 가 추정치 CI 로 기재되어 헤드라인에 표본변동 구간이 없었다) |
| `n` | 표본 크기 | 설계별로 다르면 행마다 명시 |
| `source_json` | 산출물 상대경로 | |
| `json_path` | 산출물 내 경로 (`estimates.panelA.ci95`) | 리스트 인덱스는 `.0` `.1` |
| `code` / `sha256_16` | 생성 스크립트와 실행 시 해시 | 산출물의 자기기록과 동기화 |
| `path_status` | GO / PARTIAL / KILL / OK / **SUPERSEDED** | SUPERSEDED 행은 삭제하지 않는다 — 검증기가 여기서 폐기 수치 차단목록을 자동 도출한다 |

## 운용 규칙
- 산출물을 재실행해 sha 가 바뀌면 해당 행 전부 sha 동기화.
- 설계가 바뀌어 옛 행을 폐기하면 **SUPERSEDED 로 표시**하고 새 id 로 새 행. 덮어쓰지 않는다.
- 파생값(합·차·범위)은 `json_path` 가 객체를 가리키게 두고 claim 에 계산식을 적는다.
