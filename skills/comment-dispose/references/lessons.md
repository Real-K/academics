# 리뷰 반영에서 배운 것 (P-014 리뷰 1~10 · P-016 리뷰 1~5)

## 리뷰어 수치도 검증 대상이다
- "Figure 2 의 z 3.87 vs Table 3 의 3.96 은 stale" → 아니었다. 같은 0.7101 을 두 스크립트가 **독립 2,000회 위약 추출**로 재평가한 MC 변동. 조치는 라벨 정리(그림에서 z 생략)였고 재계산이 아니었다.
- "364 vs 367 은 동시에 참일 수 없다" → 두 계수는 **다른 창 규칙**(12개월 완비 vs ≥6개월)이었다. 조치는 규칙을 표·본문에 명시.
- "패널이 2026-05 에 끝나는데 딜이 2026-06 까지" → 매칭 공변량이 전부 사전월이라 정상. 한 문장 설명.
- 반대로 리뷰어가 맞았던 것: 표 번호 재편 후 구 번호 잔존(11곳) · 캡션 블록 구판 · "every specification" 전칭 · Table 5 "common sample n=301"(행은 301/181/189) · 원장 중복 claim_id.

## 파급 범위가 큰 요구는 대안을 평가한다
- "p 를 전부 양측으로" → primary 양측 p 는 0.001 로 결론 불변이지만 상단꼬리로 저장된 산출물 10여 종과 부록 표를 재계산해야 했다. 리뷰어가 허용한 대안(방향 계열은 상단꼬리 유지 + 라벨 명시 + 참고용 양측 p 한 번)을 택하고 **사유를 대장에 기록**. 원고에는 "재계산 비용" 언급 금지 — 근거는 "directional hypothesis" 하나.

## 편집 순서를 어기면 어긋난다
핵심 원고 → 저널 셸(초록·서론은 빌더 안에 따로 있음) → 표 빌더 → 그림 빌더 → **캡션 블록(코드 안)** → 부록 → 색인. 한 곳만 고치면 검증기가 잡지 못하는 곳(캡션·셸)에서 구판이 살아남는다.

## 삭제와 이동의 차이
"불리한 결과는 보고할 필요 없어" 라는 지시는 **부록 이동**으로 이행한다(rules/10). 삭제하면 무결성 위반이고, 리뷰어는 결국 찾는다.

## 검증기가 통과해도 끝이 아니다
전역 풀 수치 검증기는 폐기된 설계의 값이 산출물 풀 어딘가에 남아 있으면 통과시킨다. 잔존 스윕 + 앵커 검사 + 참조 해석기까지 돌린 뒤에만 "반영 완료".
